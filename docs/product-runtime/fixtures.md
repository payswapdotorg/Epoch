# The Product Fixture Format (W046)

Deterministic fixture sets for the journey system (spec/journey-validation.md), used by W047/W048/W049 journey validation. Generated by `services/application-gateway/src/fixtures.ts` through the REAL kernels; committed under `qa/fixtures/` + `spec/journeys/fixtures/`.

## Byte-stability (the contract)

- **Frozen clocks**: every instant comes from the `FIXTURE_INSTANTS` series (2026-03-02T08:00Z..18:00Z, one-hour steps). Zero wall-clock reads (a test asserts every instant in the fixtures is from the frozen series).
- **Seeded ids**: fixed slugs everywhere (tenants, principals, solutions, programs, deliveries, activities).
- **Canonical JSON**: stable key order; every file ends with a newline; digests are over the exact file bytes.
- **Rerun-stable digests**: the drift test re-renders and compares byte-for-byte; the registry records per-file SHA-256 digests; the fixture records carry kernel-verified content digests (real seals — `sealSolutionVersion`, `buildProgramOfWork`, `openDeliveryRecord`, `EvidenceStore.add`), never fabricated values.

| `software` | repo/ticket/release: checkout v2 (repositories, pipelines, release train, storypoint lines, pipeline-green gate) | `epoch-fixture-software-v1.0.0` |

Plus `qa/fixtures/registry.json` (per-file digests + the domain digest anchors) and `spec/journeys/fixtures/journey-fixtures.json` (the journey-system contract: per journey + domain — fixture id, scenario-script reference, preconditions, expected outcome digests).

## The J07/J08/J11 scenario scripts

Typed step scripts (`JourneyScenarioScript`): `{scriptId, journeyId, domain, description, steps: [{stepId, action, input, expectation}]}`.

- **J07 (offline work, queue, reconnect, idempotent sync)**: enqueue a field-observation intent as a pending projection -> the first drain fails transiently (still pending) -> the reconnect drain applies it through the Action Gateway path with the idempotency key -> a replay of the same key returns the RECORDED outcome (never double-apply).
- **J08 (cross-device handoff)**: mobile captures the world projection -> desktop inspects -> the SAME world digest (authoritative state resolved through Epoch) -> the session scope is identical -> the local projection cache admits the server projection by digest.
- **J11 (recovery from network/session/connector failures)**: session expiry (re-authenticate) -> re-authentication -> connector failure (retry-with-backoff) -> successful retry (correlation causation chain) -> an authority rejection surfaced verbatim.

## Regeneration

```
EPOCH_UPDATE_FIXTURES=1 pnpm --filter @epoch/application-gateway test fixtures-drift
```

The drift test (`services/application-gateway/test/fixtures-drift.test.ts`) re-renders on every run and fails on any byte drift, so committed fixtures can never silently diverge from the kernels.
