# @epoch/agent-protocol

Epoch **Agent Protocol v1** — runtime implementation (kernel layer, Work
Order W003). Provider-neutral agent registration, capability/tool
declarations, and the shared protocol primitives (canonical JSON
serialization, SHA-256 digests, message admission pipeline) reused by
`@epoch/action-protocol`.

The published contract surface for this package lives at `contracts/agent/`
(TypeScript declarations, JSON Schema projection, manifest with digests).
This package is the runtime implementation of that contract;
`contracts/agent/parity.ts` proves type identity at compile time.

## Layer and dependencies

- Epoch layer: `kernel` (declared in `package.json` under `epoch.layer`).
- Runtime dependency: `zod` (frozen pnpm catalog — see
  `scripts/DEPENDENCY-BASELINE.md`).
- No Node APIs in runtime code: canonicalization and SHA-256 are
  dependency-free and runtime-neutral (web/desktop/mobile/Node), per
  architecture lock rule 14. `node:` imports appear only in tests, as
  reference material.

## Public API overview

- `parseAgentRegistration(input)` / `validateAgentRegistration(input)` —
  admit an `agent.registration` message through the full pipeline
  (version gate → kind gate → zod validation → canonical serialization →
  digest). The parse result carries the canonical JSON and its SHA-256
  digest (exact-revision evidence form); failures are typed
  (`version-mismatch` | `kind-mismatch` | `schema-violation`).
- `parseCapabilityDeclaration` / `validateCapabilityDeclaration` — admit a
  standalone capability declaration document.
- Schemas: `AgentRegistrationSchema`, `CapabilityDeclarationSchema`,
  `ToolDeclarationSchema`, `ParameterSpecSchema`, `ExecutorSchema`,
  `AuthorityDeclarationSchema`, `EvidenceRequirementsSchema`,
  `CostProfileSchema`, `LatencyProfileSchema`, and the shared primitives
  (`TimestampSchema`, `MessageIdSchema`, `AgentIdSchema`,
  `QualifiedTypeReferenceSchema`, `JsonValueSchema`).
- Shared primitives re-exported for the action protocol and consumers:
  `canonicalJsonStringify`, `canonicalDigest`, `sha256Hex`,
  `admitMessage`, `unwrapOrThrow`, `ProtocolValidationError`.
- `AGENT_PROTOCOL_SCHEMA_SURFACE` — the ordered registry of every published
  data type with its schema; `renderAgentContractFiles()` deterministically
  emits the `contracts/agent` artifact set from it.

## Contract artifacts (emission and drift)

`contracts/agent/manifest.json` and `contracts/agent/schemas/*.json` are
committed artifacts generated by `renderAgentContractFiles()` (zod 4
`z.toJSONSchema`, draft 2020-12). The drift test re-renders them and
compares byte-for-byte, so the artifacts can never silently diverge from
the implementation. To regenerate after an intentional schema change:

```sh
EPOCH_UPDATE_CONTRACTS=1 pnpm --filter @epoch/agent-protocol test contract-drift
```

JSON Schema fidelity is structural-only (zod refinements are runtime
enforcement); see `contracts/agent/README.md`.

## Authority split (architecture lock rules 2/3)

Agents propose; only the Action Gateway (W022) authorizes and executes.
`AuthorityDeclarationSchema` encodes this structurally:
`executionAuthority` admits exactly the literal `"none"`, so a registration
cannot express execution authority at all. See `contracts/agent/README.md`
for the full contract documentation.

## Testing

`pnpm --filter @epoch/agent-protocol test` runs the vitest suite:
canonical serialization determinism, SHA-256 NIST vectors plus
`node:crypto` cross-verification, version/kind gate precedence, positive
round-trips for every executor kind, and negative batteries for authority
boundaries, malformed declarations, envelope discipline, provider
neutrality, and contract drift.

## Notes and limitations

- The `typecheck` script compiles two programs: the package
  (`tsconfig.json`) and the contract parity program
  (`tsconfig.contracts.json`, which type-checks `contracts/agent` against
  this package's source via a path mapping — a compile-time-only assertion,
  not a runtime dependency edge).
- This package hosts the shared protocol plumbing (envelope, versioning,
  canonical serialization, digests) because it is the base protocol
  package; `@epoch/action-protocol` depends on it (kernel → kernel is an
  allowed layer edge). A future `protocol-core` split is recorded as an
  architecture question in the W003 PR.
